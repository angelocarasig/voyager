# Voyager v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS file browser with a sidebar, list and grid views, Quick Look and full
keyboard navigation, which never blocks the UI while listing slow NAS folders.

**Architecture:** A SwiftUI app around `NavigationSplitView`. One `@MainActor @Observable`
`BrowserModel` owns the current folder, history, listing and loading state. It calls an
injectable loader that lists folders off the main actor. Views read the model and call its
methods; they hold no navigation logic.

**Tech Stack:** Swift 6, SwiftUI, AppKit (`NSWorkspace`), Foundation `FileManager`, Swift
Testing. No third-party dependencies.

**Spec:** `docs/design.md` (with `docs/brief.md` for context)

## Global Constraints

- Deployment target macOS 26. APIs introduced in macOS 27 need `#available` checks.
- App Sandbox off. Distributed outside the Mac App Store.
- No third-party dependencies.
- Tests use Swift Testing (`import Testing`, `@Test`, `#expect`), not XCTest.
- Directory listing never runs on the main actor.
- v1 performs no file operations: no rename, trash, copy, move or drag and drop.
- Folders are not watched for changes. `⌘R` reloads.
- Code style: a blank line before and after every block statement except at the start or end
  of its enclosing block. No comments unless they say something the code cannot.
- Do not commit. The user commits when they ask; commit messages are `<type>: <subject>`.

## Review Focus

1. **App bundles and packages** (`.app`, `.photoslibrary`) open in their app, not as folders.
   Test in Task 1.
2. **Unreachable folders** (unmounted NAS share, permission denied) show an inline error and
   keep the sidebar usable. Test in Task 2.
3. **Rapid navigation** on a slow share: a stale listing never replaces the folder the user
   moved to. Test in Task 2.
4. **Symlinks to folders** open as folders. Test in Task 1.
5. **Typed paths** (`⌘L`) with `~`, a trailing slash or a path that does not exist: the first
   two navigate, the last shows an error without leaving the current folder. Test in Task 5.

### Task 2: BrowserModel

**Files:**
- Create: `Voyager/Browser/BrowserModel.swift`
- Test: `VoyagerTests/BrowserModelTests.swift`

**Interfaces:**
- Consumes: `FileItem`, `DirectoryLoader.load(_:)`
- Produces:
  - `@MainActor @Observable final class BrowserModel`
  - `init(start: URL, load: @escaping @Sendable (URL) async throws -> [FileItem] = DirectoryLoader.load)`
  - Read-only state: `current: URL`, `items: [FileItem]`, `isLoading: Bool`, `error: String?`, `canGoBack: Bool`, `canGoForward: Bool`
  - Writable state: `selection: Set<FileItem.ID>`, `sortOrder: [KeyPathComparator<FileItem>]`
  - `func navigate(to folder: URL) async`, `goBack() async`, `goForward() async`, `goUp() async`, `reload() async`
  - `func open(_ item: FileItem) async`: navigates when `item.opensAsFolder`, otherwise calls `NSWorkspace.shared.open(item.url)`

- [ ] **Step 1: Write the failing tests**

Tests inject a fake `load` closure. For the race test, the fake waits on a continuation that
the test resumes, so no timing is involved.

```swift
@Test func navigateLoadsItemsAndClearsSelection() async
#expect(model.current == folderB)
#expect(model.items.map(\.name) == ["b1"])
#expect(model.selection.isEmpty)
#expect(model.isLoading == false)

@Test func backForwardAndUp() async
// navigate A -> B, goBack, goForward, goUp
#expect(model.current == folderA)   // after goBack
#expect(model.canGoForward)
#expect(model.current == folderB)   // after goForward
#expect(model.current == folderB.deletingLastPathComponent())   // after goUp

@Test func failedLoadShowsErrorAndEmptiesList() async
// fake throws CocoaError(.fileReadNoPermission) for folderB
#expect(model.current == folderB)
#expect(model.items.isEmpty)
#expect(model.error != nil)

@Test func staleLoadNeverReplacesNewerFolder() async
// start navigate(to: slow), then navigate(to: fast) and let it finish, then release slow
#expect(model.current == fast)
#expect(model.items.map(\.name) == ["fast1"])

@Test func goUpAtRootDoesNothing() async
// start at "/"
#expect(model.current == URL(filePath: "/"))
#expect(model.canGoBack == false)
```

- [ ] **Step 2: Run the tests and confirm they fail**

Run: `xcodebuild test -scheme Voyager -destination 'platform=macOS' -only-testing:VoyagerTests/BrowserModelTests`
Expected: build failure, `BrowserModel` not defined.

- [ ] **Step 3: Implement `BrowserModel`**

Hold the running load in a `Task` property; `navigate` cancels it before starting the next.
After the load returns, apply the result only if the task was not cancelled and `current` is
still the folder it loaded. History is two stacks of URLs; `navigate` clears the forward stack.
`error` is the error's `localizedDescription`. Sorting applies `sortOrder` to `items` after each
load and whenever `sortOrder` changes, with folders always first.

- [ ] **Step 4: Run the tests and confirm they pass**

Same command. Expected: 5 tests pass.

### Task 4: Window, sidebar, list view and path bar

**Files:**
- Create: `Voyager/Views/ContentView.swift`, `Voyager/Views/SidebarView.swift`, `Voyager/Views/FileListView.swift`, `Voyager/Views/PathBar.swift`
- Modify: `Voyager/VoyagerApp.swift`

**Interfaces:**
- Consumes: `BrowserModel`, `sidebarSections(home:nasRoot:volumes:)`, `breadcrumbs(for:)` from Task 5 is not yet available, so the path bar shows `current.pathComponents` directly in this task and switches to `breadcrumbs(for:)` in Task 5.
- Produces: `ContentView(model: BrowserModel)`. The window starts at the home folder.

- [ ] **Step 1: Build the views**

- `ContentView`: `NavigationSplitView` with `SidebarView` and the content area. Toolbar: back
  and forward buttons (disabled from `canGoBack`/`canGoForward`), `PathBar`, a
  `ProgressView().controlSize(.small)` shown while `isLoading`.
- Content area: `FileListView`, or `ContentUnavailableView(model.error ?? "", systemImage: "exclamationmark.triangle")` when `error != nil`.
- `SidebarView`: `List` with one `Section` per `SidebarSection`; each row is a `Label` with the
  folder name and `NSWorkspace.shared.icon(forFile:)`. The row matching `model.current` is
  selected. Selecting a row calls `navigate(to:)`.
- `FileListView`: `Table(model.items, selection: $model.selection, sortOrder: $model.sortOrder)`
  with Name (icon and name), Size (`ByteCountFormatter`, `--` for folders), Modified (relative
  date) and Kind. `.contextMenu(forSelectionType: FileItem.ID.self, menu: { _ in }, primaryAction:)`
  opens the item, which covers double-click and Return.
- `PathBar`: a row of buttons, one per path component, each navigating to that ancestor.

### Task 5: Keyboard, path entry and Quick Look

**Files:**
- Create: `Voyager/Browser/TypeAhead.swift`, `Voyager/Browser/PathInput.swift`
- Modify: `Voyager/VoyagerApp.swift`, `Voyager/Views/FileListView.swift`, `Voyager/Views/PathBar.swift`
- Test: `VoyagerTests/TypeAheadTests.swift`, `VoyagerTests/PathInputTests.swift`

**Interfaces:**
- Consumes: `BrowserModel`, `FileItem`
- Produces:
  - `func typeAheadMatch(_ prefix: String, in items: [FileItem]) -> FileItem.ID?`: first item whose name starts with `prefix`, case- and diacritic-insensitive
  - `func resolvePath(_ input: String, home: URL) -> URL?`: expands `~`, trims whitespace and a trailing slash, returns `nil` unless the path exists and is a folder
  - `func breadcrumbs(for url: URL) -> [URL]`: `/` first, `url` last

```swift
#expect(resolvePath("~/", home: tempHome) == tempHome)

@Test func resolvesTrailingSlashAndWhitespace()
#expect(resolvePath("  \(folder.path)/ ", home: tempHome) == folder)

@Test func missingPathResolvesToNil()
#expect(resolvePath("/no/such/folder", home: tempHome) == nil)

@Test func filePathResolvesToNil()
#expect(resolvePath(file.path, home: tempHome) == nil)

@Test func breadcrumbsFromRoot()
#expect(breadcrumbs(for: URL(filePath: "/mnt/NAS/Media")).map(\.path) == ["/", "/mnt", "/mnt/NAS", "/mnt/NAS/Media"])
```

- [ ] **Step 5: Wire the keys**

| Key | Where | Action |
|---|---|---|
| Return, double-click | `Table` `primaryAction` (Task 4) | `open` |
| `⌘↓` | menu command | `open` the single selection |
| Backspace (`.delete`), `⌘↑` | `onKeyPress` on the view / menu command | `goUp` |
| `⌘[`, `⌘]` | menu commands | `goBack`, `goForward` |
| `⌘L` | menu command | switch `PathBar` to a focused `TextField`; Return calls `resolvePath` and navigates, or shows the error inline and stays put; Escape cancels |
| `⌘R` | menu command | `reload` |
| Space | `onKeyPress(.space)` | toggle Quick Look on the selection |
| Letters | `onKeyPress(characters: .alphanumerics)` | append to a prefix buffer, select `typeAheadMatch`; the buffer clears on the next key press more than 1 s after the last one |

Menu commands live in `VoyagerApp` under a `Go` menu and reach the model through
`@FocusedValue`. Quick Look uses `.quickLookPreview($previewURL, in: selectedURLs)`.
`PathBar` switches from `current.pathComponents` to `breadcrumbs(for:)`.

- [ ] **Step 6: Verify in the running app**

Build with zero warnings, then check each by keyboard only:
- Arrow down, Return opens a folder; Backspace goes back up.
- `⌘[` and `⌘]` move through history.
- `⌘L`, type `~/Documents`, Return navigates; type `/nope`, Return shows an error and stays.
- Typing `do` in the home folder selects Documents or Downloads.
- Space shows Quick Look for a file and closes it again.

### Task 6: Grid view and the view mode setting

**Files:**
- Create: `Voyager/Views/FileGridView.swift`
- Modify: `Voyager/Views/ContentView.swift`, `Voyager/VoyagerApp.swift`

**Interfaces:**
- Consumes: `BrowserModel`, the keyboard handlers from Task 5
- Produces: `enum ViewMode: String { case list, grid }`, stored with `@AppStorage("viewMode")`

- [ ] **Step 1: Build the grid and toggle**

- `FileGridView`: `ScrollView` with `LazyVGrid(columns: [GridItem(.adaptive(minimum: 96))])`.
  Each cell is a 64pt `NSWorkspace` icon above the name, two lines, middle truncation. Click
  selects (`⌘`-click adds), double-click opens. Selection uses `model.selection`.
- Arrow keys move the selection: left and right by one, up and down by the column count, which
  is read from the grid's width with `onGeometryChange`.
- The type-ahead, Space, Return and Backspace handlers from Task 5 apply to the grid too.
- Toolbar: a segmented `Picker` bound to the view mode. `⌘1` list, `⌘2` grid, in a `View` menu.

- [ ] **Step 2: Verify in the running app**

Build with zero warnings, then check each:
- `⌘2` shows the grid; moving to another folder keeps the grid; relaunching keeps the grid.
- Arrow keys move through the grid by item and by row.
- Return, Space and typing work the same as in the list.
- Selection is kept when switching between list and grid.
